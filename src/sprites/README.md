# Локальные sprite-обёртки

Каталог `src/sprites/` содержит тонкие обёртки над sprite-библиотеками PlantUML.

## Зачем

DSL не должен привязываться к реализации конкретной sprite-библиотеки. Обёртки
дают пользователю **стабильное имя спрайта** (`$spring-icon`, `$ma_database`,
`$server`), которое не зависит от версии PlantUML и от пути include.

## Содержимое

| Файл | Спрайт | Источник |
|---|---|---|
| `spring-icon.puml` | Spring Boot | `<logos/spring-icon>` |
| `database.puml`    | PostgreSQL/база | `<material/database>` |
| `server.puml`      | RabbitMQ/сервер | `<tupadr3/font-awesome/server>` |

Каждый файл предоставляет функцию-обёртку (`$getSpringIcon`, `$getDatabase`,
`$getServer`), которая нормализует формат алиаса (`<$name>` или `<&name>`).

## Авто-подключение спрайтов

`src/C4/Sprites.puml` — это **bundle**, который подключает все необходимые
stdlib-спрайты (`!include <logos/...>`) и сам транзитивно подключается из
`src/C4/Context.puml`. Поэтому пользователю достаточно одного include DSL —
спрайты для известных технологий становятся доступны автоматически:

```plantuml
@startuml
!include <путь/к/dsl>/C4/Context.puml

$Container("api", "API", "Spring Boot", "Backend")
@enduml
```

Никаких ручных `!include <logos/...>` не требуется.

> **Примечание о PlantUML 1.2026.5:** stdlib-include работают даже после
> файловых include и внутри транзитивно подключаемых файлов (проверено
> экспериментально). Ранние ограничения, зафиксированные в предыдущей версии
> этого документа, оказались неверными.

## Использование в playground/тестах

В playground-примерах подключается только DSL — спрайты подключаются сами
через bundle:

```plantuml
!include <путь/к/dsl>/C4/Context.puml

$Container("api", "API", "Spring Boot", "Backend")
```

DSL получает имя спрайта из справочника технологий автоматически. Если
технология неизвестна или не имеет стандартного спрайта, контейнер
рендерится без пиктограммы.

## Как добавить новую обёртку

Функции-обёртки (`$getSpringIcon`, `$getDatabase`, `$getServer`) в этом
каталоге нормализуют формат алиаса спрайта (`<$name>` или `<&name>`).
Они не подключают stdlib — это делает bundle (`src/C4/Sprites.puml`).

1. Скопировать `spring-icon.puml` под новым именем.
2. Заменить имя функции `$getSpringIcon` на новое.
3. Заменить комментарии.
4. Имя спрайта, которое генерирует PlantUML при `!include <...>`, можно увидеть,
   открыв файл из stdlib — он содержит `sprite $<name> ...`. Именно это имя
   и нужно передавать в `$sprite=...`.

## Состав bundle

В `src/C4/Sprites.puml` включаются **только** спрайты, реально существующие
в stdlib PlantUML (несуществующий `!include <logos/...>` ломает всю диаграмму).
Текущий набор: `spring-icon`, `postgresql`, `rabbitmq`, `redis`, `mysql`,
`mongodb`, `kafka`, `nodejs`.

Чтобы добавить новый спрайт в bundle:
1. Убедиться, что `!include <logos/<name>>` компилируется без ошибок.
2. Добавить строку в `src/C4/Sprites.puml`.
3. Добавить/обновить запись в `$__tech_catalog()` (`src/C4/Technologies.puml`),
   указав имя спрайта.

## Авто-подбор спрайта по технологиям

Если у контейнера не задан явный спрайт (через `$sprite=` в дескрипторе или
декораторе), DSL автоматически подбирает пиктограмму по списку его технологий
(сценарий 3.3 issue #22).

За подбор отвечают функции в `src/C4/Technologies.puml`:

- `$get_container_main_tech_from_technologies($technologies)` — выбирает
  наиболее значимую технологию и возвращает её **каноническое имя** из
  справочника (не псевдоним спрайта), т.к. библиотеки пиктограмм могут быть
  любыми внешними.
- `$get_sprite_from_technologies($technologies)` — вызывает первую, затем ищет
  имя спрайта в справочнике; возвращает `""`, если технология неизвестна или
  не имеет стандартного спрайта.

Приоритет категорий при выборе основной технологии:
1. framework / datastore / queue / cache (Spring Boot, PostgreSQL, RabbitMQ, Redis, …)
2. platform (JVM, .NET, Node.js)
3. language (Java, C#, Python, …)

У технологии может быть несколько альтернативных имён (например `spring`,
`spring-boot`, `spring boot` → `Spring Boot`). Карта сопоставления
"технология + альтернативные имена → спрайт" хранится в
`src/C4/technologies_catalog.puml` — файле с массивом записей
`{canonical, aliases[], category, sprite}`, где `aliases` группирует
все альтернативные имена технологии в одном объекте. Редактируется без
изменения логики поиска.

### Расположение каталога и SET_SPRITES_MAP

Каталог подключён в `src/C4/Technologies.puml` через `!include
technologies_catalog.puml`, который резолвится **относительно расположения
файла**, а не cwd. Поэтому каталог доступен при любом cwd запуска (IDE с
temp-каталогом, онлайн-сервер) без дополнительной настройки.

`SET_SPRITES_MAP($path)` подменяет встроенный каталог на пользовательский
JSON-файл (путь задаётся относительно cwd, как у `%load_json`). Нужна только
тем, кто хочет вести собственный список технологий:

```plantuml
@startuml
!include <путь/к/dsl>/C4/Context.puml

'' Подменить каталог на собственный JSON
SET_SPRITES_MAP("custom-technologies.json")

$Container("api", "API", "Spring Boot", "Backend")
@enduml
```

### Управление авто-подбором

Авто-подбор **включён по умолчанию**. Глобальные процедуры позволяют отключать
и повторно включать его для всей диаграммы. Имена соответствуют конвенции
stdlib C4-PlantUML (`SHOW_PERSON_SPRITE` / `HIDE_PERSON_SPRITE`):

```plantuml
@startuml
!include <путь/к/dsl>/C4/Context.puml

'' Отключить авто-подбор (контейнеры без явного $sprite рендерятся без пиктограмм)
HIDE_TECH_SPRITE_AUTO()

'' Включить обратно (состояние по умолчанию)
SHOW_TECH_SPRITE_AUTO()

$Container("api", "API", "Spring Boot", "Backend")
@enduml
```

Явный спрайт (`$sprite=` в дескрипторе или `ApplySprite(...)`) всегда имеет
приоритет над авто-подбором, независимо от состояния флага.

> **Примечание о PlantUML 1.2026.5:** встроенная `%lower_case` в этой версии
> недоступна, поэтому нормализация регистра реализована посимвольно в
> `$__to_lower()`. Разбор строк (`%splitstr`, `%splitstr_regex`) внутри
> `!function` работает корректно.

## Известные ограничения

- Спрайт задаётся **явно** через параметр `$sprite=` в `$Container(...)`,
  либо через `ApplySprite(...)`, либо **автоматически** по списку технологий
  (см. раздел «Авто-подбор спрайта по технологиям» выше).
